# دستگاه اثر انگشت — راهنمای اتصال سه برند

جیم‌پرو از سه خانوادهٔ دستگاه پشتیبانی می‌کند. صفحهٔ «اثر انگشت» در منو → دکمهٔ «دستگاه جدید» → انتخاب برند.

> اصل ثابت: **تمپلیت اثر انگشت هرگز از دستگاه بیرون کشیده نمی‌شود.** برنامه فقط «شناسهٔ کاربر + زمان + (اختیاری) جهت» را می‌گیرد. این هم ریسک حقوقی را کم می‌کند و هم انتقال دستگاه بین باشگاه‌ها را ساده.

## قاعدهٔ ورود/خروج

| `punch_mode` | معنی |
|---|---|
| `toggle` (پیش‌فرض) | دستگاه فقط ساعت می‌فرستد. اگر آخرین رکورد امروز آن عضو **بدون خروج** باشد، رکورد جدید **خروج** ثبت می‌شود؛ وگرنه **ورود**. |
| `in_out` | دستگاه خودش IN/OUT را مشخص می‌کند (ADMS state یا BioStar direction) و برنامه همان را می‌پذیرد. |

شناسهٔ کاربر روی دستگاه باید با **شمارهٔ عضویت** جیم‌پرو یکی باشد. اگر نبود، از «نگاشت شناسه» در همان صفحه وصلش کن.

## ۱) ZKTeco — دو حالت

### الف) TCP 4370 (پولینگ)
- در دستگاه: `Comm → Ethernet` را تنظیم کن؛ IP ثابت بده (یا در روتر DHCP reservation).
- در برنامه: برند ZKTeco، حالت «اتصال شبکه (TCP 4370)»، IP و پورت ۴۳۷۰.
- «تست اتصال» تعداد کاربر/لاگ و ظرفیت را نشان می‌دهد. «خواندن رکوردها» لاگ‌ها را می‌آورد.
- محدودیت‌ها: اگر روی دستگاه «Comm Key» گذاشته‌ای، الان پشتیبانی نمی‌شود؛ خاموشش کن. برخی فریمورها ۴۳۷۰ را قفل می‌کنند → از حالت ADMS استفاده کن.

### ب) ADMS / Push (توصیه‌شده)
- برنامه روی پورت **۸۰۹۰** یک شنوندهٔ HTTP اجرا می‌کند (`/iclock/cdata`).
- در دستگاه: `Comm → Cloud Server Settings` → `Server Address` = **IP رایانهٔ منشی**، `Server Port` = **8090**، `Enable Domain Name` = خاموش.
- سریال دستگاه را در فرم دستگاه وارد کن؛ رکوردها لحظه‌ای می‌رسند.
- تأیید: بالای صفحهٔ «اثر انگشت» بنر «شنوندهٔ ADMS» روشن است و سریال دستگاه را با تعداد رکورد نشان می‌دهد.
- نیاز شبکه: دستگاه و رایانه در یک LAN؛ پورت ۸۰۹۰ در فایروال ویندوز باز باشد (`New-NetFirewallRule -DisplayName GymPro-ADMS -Direction Inbound -LocalPort 8090 -Protocol TCP -Action Allow`).

## ۲) Suprema (BioStation / FaceStation با BioStar 2)
- در BioStar 2 یک کاربر API بساز (Settings → User / API) و روی دستگاه/سرور BioStar فعال کن.
- در برنامه: برند Suprema، حالت «BioStar 2 (REST)»، آدرس سرور BioStar، پورت ۴۴۳، نام کاربری و رمز API.
- برنامه با `POST /api/login` وارد می‌شود، `bs-session-id` می‌گیرد و رکوردها را از `/api/event_logs/search` می‌خواند.
- گواهی SSL خودامضا: برنامه فعلاً آن را رد می‌کند؛ یا گواهی معتبر بگذار یا از BioStar با HTTP داخلی استفاده کن.

## ۳) Futronic (FS80 / FS88)
فوترونیک اسکنر است، نه ترمینال شبکه. دو راه:

**الف) پوشهٔ CSV** — نرم‌افزار سازنده فایل تردد می‌سازد؛ در برنامه همان **پوشه** را بده. هر فایل CSV با قالب‌های رایج (`شماره,تاریخ ساعت` یا `شماره,IN/OUT,تاریخ`) خوانده می‌شود.

**ب) پل محلی HTTP** — اگر پل کوچکی روی همان رایانه اجرا می‌کنی، آدرس و پورت (پیش‌فرض ۹۰۹۹) را بده؛ برنامه `GET /punches?since=…` را می‌خواند.

- محدودیت صادقانه: SDK فوترونیک ویندوزی و بسته است؛ یکپارچه‌سازی مستقیم بدون پل یا فایل ممکن نیست.

## آزمون بدون سخت‌افزار

در همان صفحه، «خواندن رکوردها» برای دستگاه ADMS چیزی برنمی‌گرداند چون رکورد را دستگاه push می‌کند. برای آزمون منطق:
- `POST http://127.0.0.1:8090/iclock/cdata?SN=<سریال>&table=ATTLOG` با بدنهٔ `1<TAB>2026-11-21 14:20:00<TAB>0<TAB>1<TAB>0`
- یا `bio:simulate` از طریق IPC.

## آنچه تست شد (بدون دستگاه واقعی)

| مورد | نتیجه |
|---|---|
| مهاجرت‌ها | `0004` (سه جدول دستگاه/رکورد/نگاشت)، `0005` (روش `fingerprint` در تردد)، `0006` (وضعیت ADMS) روی پایگاه موجود اجرا و پاس شد |
| منطق ورود/خروج | دو رکورد پی‌درپی برای یک عضو: اول `in` با `checkinId`، بعد `out` روی همان رکورد؛ زمان از دستگاه گرفته شد نه ساعت رایانه |
| عضو ناشناس | شناسهٔ ۹۹۹۹ → رکورد با وضعیت `unknown_member` ذخیره شد و خطا نداد |
| ADMS | handshake واقعی `GET /iclock/cdata?SN=…` پاسخ `GET OPTION FROM` داد؛ `POST` با دو خط ATTLOG → ۲ رکورد ثبت، یکی `applied/out` |
| خطای شبکه | دستگاه خاموش: پیام فارسی «دستگاه پاسخ نداد…» (نه `[object Object]`، نه معلق‌ماندن) |
| نصب NSIS | نصب سایلنت در `%LOCALAPPDATA%\Programs\GymPro`، اجرا با `portable:false` و داده در `%APPDATA%\gympro\data` |

## محدودیت‌های شناخته‌شده

- ثبت کاربر/اثر انگشت **روی** دستگاه از داخل برنامه انجام نمی‌شود (فقط خواندن و نگاشت). این کار را با پنل خود دستگاه انجام بده.
- Comm Key زکتکو و گواهی خودامضای Suprema پشتیبانی نمی‌شود.
- پولینگ خودکار پس‌زمینه (هر ۳۰ ثانیه) فقط برای TCP 4370/CSV پل‌گذاری شده؛ برای ADMS نیازی نیست چون push است.
