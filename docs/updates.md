# به‌روزرسانی نرم‌افزار

نسخه‌یابی از **GitHub Releases** انجام می‌شود؛ مسیر دوم (مانیفست امضاشده با Ed25519 روی سرور اختصاصی) هم در تنظیمات موجود است. وضعیت در چند جا دیده می‌شود:

- **نوار بالای برنامه:** ۲۰ ثانیه پس از اجرا (و هر ۶ ساعت) نسخهٔ منتشرشده با نسخهٔ نصب‌شده مقایسه می‌شود؛ اگر جدیدتر بود نوار «نسخهٔ جدید X منتشر شده است» با دکمهٔ «مشاهده و به‌روزرسانی» می‌آید. قابل بستن است.
- **تنظیمات → به‌روزرسانی نرم‌افزار:** نسخهٔ نصب‌شده و نسخهٔ موجود، تاریخ آخرین بررسی، دکمهٔ «بررسی مجدد»، «دانلود نسخهٔ جدید» و پس از دانلود «نصب نسخهٔ X و راه‌اندازی مجدد».
- **بج نسخه در هدر** (`v1.2.0`): با کلیک، به تنظیمات می‌رود.
- وقتی نسخهٔ نصب‌شده همان آخرین نسخه باشد: **«نسخه شما به‌روز است.»**

### انتشار نسخهٔ جدید (برای مالک)

```bash
node scripts/release.mjs 1.2.2 "رفع اشکال گزارش‌ها|افزودن ستون جدید"
```

این اسکریپت نسخهٔ `package.json` را می‌نویسد، بیلد می‌کند، نصب‌کننده را می‌سازد، تگ `v1.2.2` را می‌سازد و `.exe` + `.blockmap` را ضمیمه می‌کند. کاربران حداکثر ۶ ساعت بعد (یا با «بررسی مجدد») اطلاعیه می‌گیرند.

**مخزن خصوصی:** برنامه برای خواندن Releases به یک **توکن گیت‌هاب با دسترسی خواندن** نیاز دارد؛ در تنظیمات → «تنظیمات منبع به‌روزرسانی» → «توکن گیت‌هاب» ذخیره می‌شود. بدون توکن، GitHub پاسخ 404 می‌دهد و پیام «هنوز هیچ نسخه‌ای منتشر نشده است» نمایش داده می‌شود.

اگر برای نسخه‌ای فایل نصبی ضمیمه نشده باشد، دکمهٔ «باز کردن صفحهٔ انتشار» نمایش داده می‌شود (دانلود از مرورگر).
