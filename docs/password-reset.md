# ریست رمز عبور

دو رمز جدا وجود دارد. مسیر درست را انتخاب کنید.

## ۱) رمز ورود برنامه (باشگاه) — «رمز عبورم را فراموش کرده‌ام»

سه مسیر، از آسان به آخرین راه‌حل. هیچ‌کدام رمز قبلی را نمی‌خواهد.

### الف) کد بازیابی (بدون اینترنت، از داخل برنامه)

اگر هنوز می‌توانید وارد شوید:

1. **تنظیمات → کاربران** → روی کاربر → **«کد بازیابی بساز»**
2. کد یک‌بارمصرف تولید می‌شود؛ به کاربر بدهید.
3. در صفحهٔ ورود → **«رمز عبور را فراموش کرده‌ام»** → تب **کد بازیابی**: نام کاربری + کد + رمز جدید.
4. برنامه یک کد بازیابی **تازه** نشان می‌دهد — آن را جایی امن نگه دارید.

کد در جدول `users.recovery_hash` (scrypt) ذخیره می‌شود، یک‌بار مصرف است و با هر استفاده کد جدید صادر می‌شود.

### ب) توکن پشتیبانی (وقتی دسترسی به برنامه هم نیست)

توکن **امضاشده با Ed25519** است، به **شناسهٔ دستگاه** بسته است و **انقضا** دارد؛ فقط مالک نرم‌افزار می‌تواند صادرش کند.

```bash
# روی سیستم مالک (کلید خصوصی فقط همین‌جاست)
node server/make-recovery.mjs <MACHINE_ID> <username> 60 "یادداشت"
```

`MACHINE_ID` را از صفحهٔ **لایسنس** در برنامهٔ کاربر (یا `node scripts/show-users.mjs`) بگیرید. خروجی: `token` (JSON) و `signature`.

کاربر: صفحهٔ ورود → «رمز عبور را فراموش کرده‌ام» → تب **توکن پشتیبانی** → هر دو مقدار + رمز جدید.

بررسی‌ها: امضا معتبر، `machineId` برابر دستگاه فعلی، `exp` نگذشته، `username` برابر توکن. اگر دستگاه عوض شده باشد توکن کار نمی‌کند (به‌عمد).

همان مسیر در **پنل مالک** هم هست: لایسنس‌ها → جزئیات کلید → «توکن بازیابی».

### ج) آخرین راه‌حل — اسکریپت آفلاین

وقتی کد و توکن هر دو از دست رفته‌اند و به پوشهٔ دادهٔ همان کامپیوتر دسترسی دارید:

```bash
# ۱) برنامه را کامل ببندید (اگر باز باشد فایل WAL قفل است)
# ۲) مسیر data و نام کاربری و رمز جدید:
node scripts/reset-password.mjs "<dataDir>" <username> "<newPassword>"

# نمونه‌ها
node scripts/reset-password.mjs "C:\Users\Pc\AppData\Roaming\gympro\data" owner "NewPass!234"
node scripts/reset-password.mjs ".qa-lic/data" owner "NewPass!234"
```

اسکریپت: hash با **scrypt** می‌سازد (همان قالب `scrypt$salt$hash`)، شمارندهٔ تلاش‌های ناموفق و قفل حساب را صفر می‌کند، `password_changed_at` را می‌نویسد و رکورد در `audit_logs` ثبت می‌کند. نشانگر «مرا به خاطر بسپار» (`.session`) هم پاک می‌شود.

> اسکریپت اگر `*.db-wal` ببیند متوقف می‌شود — یعنی برنامه باز است. اول ببندید، بعد اجرا کنید.

**تست‌شده:** رمز قدیمی رد شد، رمز جدید پذیرفته شد و ورود با نام کاربری انجام شد.

## ۲) رمز پنل مالک (سرور لایسنس) — `/var/www/gym-admin`

```bash
node scripts/reset-admin-password.mjs 'Panel!New99' /var/www/gym-admin/data
ssh root@194.56.148.100 'pm2 restart gympro-admin'
```

فقط فیلد `hash` عوض می‌شود؛ `secret` دست‌نخورده می‌ماند تا کوکی نشست‌های باز باطل نشوند. فایل با مجوز `0600` نوشته می‌شود.

**تست‌شده:** رمز جدید `303 → dashboard` داد، رمز قدیمی `401`.

### چرا «فقط ADMIN_PASSWORD را عوض کن» کار نمی‌کند

`adminStore()` در `server/admin.mjs` اول `data/admin.json` را می‌خواند و **اگر `hash` داشته باشد همان را برمی‌گرداند**؛ `ADMIN_PASSWORD` فقط وقتی استفاده می‌شود که فایل وجود نداشته باشد. پس عوض کردن متغیر محیطی بی‌اثر است.

اگر ترجیح می‌دهید از راه فایل بروید: `data/admin.json` را پاک کنید، `ADMIN_PASSWORD` را در `/root/gym-admin.env` ست کنید و `pm2 restart` بزنید. ولی **بدون** `ADMIN_PASSWORD` یک رمز تصادفی ساخته می‌شود که باید از `pm2 logs` بخوانید — به همین دلیل اسکریپت بالا بهتر است.

## ۳) پین صفحهٔ کیوسک / تأیید سریع

پین همان الگوریتم رمز را دارد (`users.pin_hash`, scrypt) و از **تنظیمات → کاربران** قابل تغییر است. اگر قفل شدید، همان اسکریپت آفلاین با ست کردن مستقیم `pin_hash` راه‌حل است.

## نکات امنیتی

- رمزها هیچ‌جا به‌صورت متن ذخیره نمی‌شوند: `scrypt` با salt تصادفی ۱۶ بایتی و کلید ۶۴ بایتی.
- «مرا به خاطر بسپار» رمز را ذخیره نمی‌کند؛ فقط یک نشانگر نشست محافظت‌شده با DPAPI.
- بعد از ۵ تلاش ناموفق حساب ۵ دقیقه قفل می‌شود؛ ریست رمز قفل را هم پاک می‌کند.
- کد بازیابی و توکن پشتیبانی هر دو یک‌بارمصرف/زمان‌دار هستند؛ در لاگ برنامه ثبت می‌شود (`auth.reset_with_code` / `auth.reset_with_token`).
