# پنل مدیریت لایسنس، آپدیت و تیکت

یک سرویس وب مستقل (بدون وابستگی npm) که همان داده‌های سرویس API برنامه را می‌خواند و می‌نویسد.

```
server/
  index.mjs            ← API مورد استفادهٔ خود برنامه (فعال‌سازی، آپدیت، تیکت)
  admin.mjs            ← همین پنل (این فایل) روی پورت ۸۸۹۹
  data/
    keys.json          ← کلیدهای لایسنس (مشترک با API)
    activations.json   ← دستگاه‌های فعال‌شده
    tickets.json       ← تیکت‌ها و پیام‌ها
    manifest.signed.json ← آخرین مانیفست آپدیت امضاشده
    admin.json         ← هش رمز مدیر + کلید امضای نشست (خودکار ساخته می‌شود)
  keys/
    license-private.pem ← کلید خصوصی امضا (فقط سرور، مود ۶۰۰)
    license-public.pem  ← کلید عمومی (داخل بیلد برنامه)
  releases/            ← فایل‌های نصب آپدیت
```

## اجرا

```bash
# ۱) سرویس API برنامه (پورت ۸۷۸۷)
node server/index.mjs

# ۲) پنل مدیریت (پورت ۸۸۹۹)
ADMIN_PASSWORD='یک-رمز-قوی' BASE_URL='https://lic.gympro.ir' node server/admin.mjs
```

اگر `ADMIN_PASSWORD` را ندهید، یک رمز تصادفی در اولین اجرا چاپ و در `server/data/admin.json` هش می‌شود.
ورود: `http://127.0.0.1:8899/login` — نشست ۱۲ ساعته، `HttpOnly` و `SameSite=Lax`، محدودیت ۱۰ تلاش ناموفق در ۱۰ دقیقه.

## پشت nginx (پیشنهادی)

```nginx
server {
  server_name lic.gympro.ir;
  location / { proxy_pass http://127.0.0.1:8899; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; }
  location /api/ { proxy_pass http://127.0.0.1:8787/; }
}
```

با `certbot --nginx -d lic.gympro.ir` گواهی بگیرید. اگر می‌خواهید پنل از اینترنت باز نشود، `allow/deny` بگذارید یا فقط با VPN.

## pm2

```bash
pm2 start server/index.mjs --name gympro-api
ADMIN_PASSWORD='...' pm2 start server/admin.mjs --name gympro-admin
pm2 save
```

## گردش کار فروش (ساخت لایسنس و تحویل به خریدار)

1. **ساخت کلید** — «لایسنس‌ها» → فرم بالا: نسخه (پایه/حرفه‌ای/سازمانی)، ماه اشتراک آپدیت (پیش‌فرض ۱۲)، تعداد دستگاه مجاز، نام خریدار. کلید خودکار مثل `GP-7K2M-9XQA-B3TD` ساخته می‌شود.
2. **تحویل** — همان کلید + لینک دانلود فایل نصبی را برای خریدار بفرستید. کلید هیچ اطلاعات حساسی ندارد؛ نگرانی از لو رفتنش نیست (فقط با Machine ID همان دستگاه معتبر است).
3. **فعال‌سازی در برنامهٔ خریدار** — صفحهٔ «لایسنس» → «فعال‌سازی» → چسباندن کلید. برنامه Machine ID را می‌فرستد، سرور امضا می‌کند و لایسنس محلی ذخیره می‌شود. از آن به بعد اجرا کاملاً آفلاین است.
4. **سقف دستگاه** — هر فعال‌سازی یک اسلات مصرف می‌کند. در صفحهٔ جزئیات کلید، هر دستگاه را می‌بینید و با «آزاد کردن اسلات» می‌توانید دستگاه دورریخته را حذف کنید.
5. **انتقال / تعویض سیستم** — یا اسلات را آزاد کنید، یا به خریدار بگویید در برنامه «غیرفعال‌سازی این دستگاه» را بزند.
6. **فراموشی رمز** — در جزئیات کلید، Machine ID و نام کاربری را بخواهید و «توکن بازیابی» بسازید (پیش‌فرض ۶۰ دقیقه). توکن به همان دستگاه گره خورده است.
7. **تمدید آپدیت** — فیلد ماه را در کلید افزایش دهید (یا کلید را غیرفعال و کلید تمدید صادر کنید). نرم‌افزار بعد از پایان اشتراک **کار می‌کند**، فقط آپدیت جدید نمی‌گیرد.

## انتشار آپدیت

1. فایل نصبی را در `server/releases/` بگذارید.
2. «آپدیت‌ها» → نسخه، نام فایل، یادداشت فارسی، اجباری/اختیاری → «امضا و انتشار».
3. مانیفست با Ed25519 امضا و `sha256` محاسبه می‌شود؛ کلاینت قبل از نصب هر دو را بررسی می‌کند (دست‌کاری نسخه در تست رد شد).

## تیکت‌ها

«تیکت‌ها» → تیکت را باز کنید → پاسخ بنویسید (وضعیت به «پاسخ داده‌شده» می‌رود) یا ببندید. برنامهٔ مشتری هر ۶۰ ثانیه وقتی آنلاین شد پاسخ‌ها را می‌کشد و نوتیفیکیشن می‌دهد.

## امنیت پیاده‌شده

| مورد | پیاده‌سازی |
|---|---|
| رمز مدیر | scrypt + salt، مقایسهٔ زمان‌ثابت |
| نشست | کوکی امضاشده با HMAC-SHA256، `HttpOnly`، `SameSite=Lax`، انقضای ۱۲ ساعته |
| CSRF | توکن وابسته به نشست در همهٔ فرم‌ها؛ توکن جعلی → ۴۰۰ (تست شد) |
| محدودیت ورود | ۱۰ تلاش ناموفق در ۱۰ دقیقه برای هر IP؛ ورود موفق شمارنده را صفر می‌کند |
| XSS | همهٔ مقادیر کاربر با `esc()` فرار داده می‌شوند |
| قالب‌بندی ورودی | نسخه/ماه/دستگاه با بازهٔ مجاز clamp می‌شوند |
| نوشتن فایل | نوشتن اتمیک (temp + rename) تا JSON نصفه‌نیمه نشود |
| کلید خصوصی | فقط روی سرور خوانده می‌شود، هرگز به کلاینت نمی‌رود |

## پشتیبان‌گیری

روزانه `server/data/` و `server/keys/` را کپی کنید. از دست دادن `license-private.pem` یعنی نتوانستن امضای لایسنس جدید؛ از دست دادن `data/admin.json` یعنی بازنشانی رمز پنل (کلید امضای نشست هم عوض می‌شود).

## استقرار روی سرور (همین سرور، اجراشده)

| مورد | مقدار |
|---|---|
| دامنه | `gym.academyr.ir` |
| سرور | `194.56.148.100` |
| مسیر برنامه | `/var/www/gym-admin` |
| داده/کلید | `/var/www/gym-admin/data` و `/var/www/gym-admin/keys` (پوشه ۷۰۰، کلیدها ۶۰۰) |
| پورت داخلی | `8899` (فقط loopback، پشت nginx) |
| pm2 | `gympro-admin` |
| متغیرها | `/root/gym-admin.env` (رمز پنل داخلش، مود ۶۰۰) |
| nginx | `/etc/nginx/sites-available/gym.academyr.ir` |
| دیپلوی مجدد | `sed 's/\r$//' deploy/setup-gym-admin.sh \| ssh root@194.56.148.100 'bash -s'` |

**رمز پنل** در `/root/gym-admin.env` است؛ برای خواندن: `cat /root/gym-admin.env`.
**تغییر رمز:** `ADMIN_PASSWORD` را در همان فایل عوض کنید **و `data/admin.json` را پاک کنید** — وگرنه رمز قدیمی (هش‌شده در admin.json) معتبر می‌ماند. بعد `pm2 restart gympro-admin`.

**TLS:** تا وقتی رکورد A دامنه به `195.28.169.23` (پارک) اشاره می‌کند certbot اجرا نمی‌شود. بعد از اصلاح DNS:

```bash
certbot --nginx -d gym.academyr.ir --redirect --non-interactive --agree-tos --register-unsafely-without-email
```

## آزمون‌های اجراشده

```bash
node scripts/test-admin.mjs           # ورود، ساخت کلید، جزئیات، توکن بازیابی، تیکت، CSRF، نشست
node scripts/test-admin-publish.mjs   # انتشار مانیفست + بررسی امضا + رد دست‌کاری
```

نتیجه: همهٔ مسیرها سبز — ورود غلط ۴۰۱، CSRF جعلی ۴۰۰، بدون نشست ۳۰۳ به `/login`، امضا معتبر و دست‌کاری نسخه رد شد.

روی سرور پس از استقرار: `/health` → ۲۰۰، `Host: gym.academyr.ir /login` → ۲۰۰ و صفحهٔ ورود، ورود صحیح ۳۰۳ و ورود غلط ۴۰۱، و کلید `GP-DEMO-0001` در فهرست لایسنس‌ها دیده شد.
